# 완화(Mitigation) 레이어 — 대시보드 연결

예방/완화/대응 3레이어 중 **완화** 레이어를 대시보드에 어떻게 연결했는지 정리한다.
- 브랜치: `feat/mitigation-ui` (`feat/onchain-attestation` b6e370f에서 분기)
- 구현일: 2026-11-17

## 1. 정의와 구성요소

`온톨로지_설계서_v0.2.docx` 2-1절에 따르면 완화는 "실행되더라도 피해 최소화 → **탐지 근거를 사용자에게 시각화 → 사전 경고**"다.
코드에 "완화"라는 이름의 모듈은 없다. 이 정의에 맞는 구성요소와 이번 작업 전 연결 상태는 다음과 같다.

| 구성요소 | 위치 | 이번 작업 전 화면 |
|---|---|---|
| 결론·위험 단계·확인 권고 | `demo/lib/decision.js` conclusion, `dashboard/src/lib/overview.js` `CONCLUSION_GUIDE` | 실데이터(개요) |
| 판단 근거, 이상이 처음 보인 때 | `decision.js` copy, `demo/lib/onset.js` | 실데이터(개요·거래 분석) |
| 판정 조건, 추론 그래프 | `decision.js` chain, `demo/lib/ontologygraph.js` | 실데이터(상세 분석) |
| 출금 차단 경고(거래) | `analysis/dynamic_analyzer.js` `hintFraudType` withdrawBlockWarning | 원자료 접힘 영역에만 |
| 유형 미확정 경고 | 같은 함수 `unclassified_warning` | 결론 "주의"로 연결 |
| 출금 차단 경고(코드)·코드 패턴 경고 | `analysis/prevention_reasoner.js` `detectWithdrawBlockWarning`·`detectCodePatternWarnings` | 원자료 접힘 영역에만(코드 카드 배지에는 반영) |
| 배포자 Risk Score | `dashboard/src/lib/risk.js`, `pages/Deployer.jsx` | 목업(`?preview=`)·데이터 없음 |
| 코드 점검 화면 | `pages/Overview.jsx` | 문구만("준비 중") |
| 권고 조치(mitigatedBy) 노드 | `ontologygraph.js` | 추론 그래프. 내용은 개발자용 코드 수정 권고 |
| 예측 이상 신호 | `prevention_reasoner.js` `predictCausalSignals` | 화면에 없음(리포트 JSON에만). 정상 시나리오에서 오탐성 신호라 계속 숨긴다(설계서 8-1) |

- 시연 시나리오 5개에서는 출금 차단 경고(거래·코드), 코드 패턴 경고, 유형 미확정 경고가 모두 **감지 안 됨**이다.
- 이 경고들이 켜지는 로그는 `analysis/logs/honeypot*_log.csv`뿐이고, 시연 시나리오가 아니다. 6번째 시나리오 추가는 범위 밖으로 결정했다.

## 2. 이번 연결: 개요 "확인해 볼 것"

개요의 "입금하기 전에 다시 확인하세요" 카드 아래에 결론별 확인 항목 2~4개를 붙였다.
- 계산: `dashboard/src/lib/mitigation.js` `checkItems({ view, risk, glossary })`
- 화면: `components/OverviewParts.jsx` `RiskActionCard`

**결론별 항목**

| 결론 | 항목 |
|---|---|
| 위험 | 돈의 흐름 · 코드 · 출금 차단 경고 · 배포자 |
| 주의 | 출금 차단 경고 · 코드 · 배포자 |
| 근거 없음 | 돈의 흐름 · 코드 · 출금 차단 경고 · 배포자 |
| 판단 불가 | 돈의 흐름 · 배포자 |

**항목별 데이터와 링크** (값은 모두 스냅샷의 기존 값이다)

| 항목 | 질문 | 값 출처(기존 규칙 재사용) | 링크 |
|---|---|---|---|
| 돈의 흐름 | 모인 돈이 어디로 갔나 | `flowLine(decision)` | 거래 분석 |
| 코드 | 컨트랙트 코드에 위험한 기능이 있나 | `codeConclusion(codeAssessment, warnings)`, 위험 수준 용어집 라벨 | 원자료(컨트랙트 소스) |
| 출금 차단 경고 | 돈이 남아 있는데 참여자 출금이 막혔나 | `warnings`의 거래·코드 출금 차단 경고와 `unclassified_warning`, `decision.facts`(출금 시도·성공 수, 실패 시점 잔고) | 원자료(감지된 패턴과 경고) |
| 배포자 | 배포한 지갑의 이력은 어떤가 | `deployerCard(riskForScenario(...))` | 배포자 위험도 |

**상태**: 감지 / 이상 없음 / 데이터 없음. "이상 없음"에는 안전색(초록)을 쓰지 않는다.

**문구 규칙**
- 확인할 곳만 안내한다. "안전합니다", "입금하지 마세요", 투자 권유 표현은 쓰지 않는다. 시험이 금지어를 검사한다.
- "이상 없음"은 "이번 분석에서는 이 신호가 없었습니다. 다른 위험은 위 결론을 참고하세요."의 뜻이다.
- 코드 위험과 배포자 위험은 항목을 나눠 적는다. 합친 등급이나 점수는 만들지 않는다.
- 카드 끝에 "확인할 곳을 안내할 뿐, 투자 여부를 권하지 않습니다."를 붙인다.
- 출금 차단 경고에서 예외적으로 이유를 덧붙이는 경우:
  - 참여자 출금 시도가 없으면 그렇다고 적는다(러그풀).
  - 실패한 출금이 잔고가 바닥난 뒤였다면 "이 경고에 해당하지 않으며 위 결론의 근거로 쓰였다"고 적는다(펌프앤덤프: 실패 5건, 실패 시점 잔고 0).

**시나리오 5개 결과**

| 시나리오 | 결론 | 돈의 흐름 | 코드 | 출금 차단 경고 | 배포자 |
|---|---|---|---|---|---|
| normal | 근거 없음 | 이상 없음 | 이상 없음(낮음) | 이상 없음 | 데이터 없음 |
| ponzi | 위험 | 감지(운영자에게 67%) | 감지(매우 높음) | 이상 없음 | 데이터 없음 |
| rugpull | 위험 | 감지(운영자에게 100%) | 감지 | 이상 없음(거래: 참여자 출금 시도 없음) | 데이터 없음 |
| laundering | 위험 | 감지(한 지갑으로 100%) | 감지 | 이상 없음 | 데이터 없음 |
| pumpdump | 위험 | 감지(내부자 3개 지갑으로 100%) | 감지 | 이상 없음(실패 5건은 잔고 바닥 뒤) | 데이터 없음 |

- 데이터 없음은 시나리오마다 배포자 한 항목뿐이다.
- 출금 차단 경고 항목은 5개 모두 "이상 없음"이다. 시연에서 이 항목이 "감지"로 보이는 경우는 없다.
- 돈의 흐름·코드·배포자 항목은 아래 "이렇게 판단했습니다" 3카드와 내용이 겹친다. 카드는 근거 설명이고, 항목은 확인할 곳 안내다.

## 3. 문구 수정

- 히어로 완화 문구(`dashboard/src/lib/hero.js` `VALUE_LINES`)
  - 바꾼 뒤: "판단 근거와 이상이 처음 보인 시점을 보여 줘, 어떤 경고 신호를 확인해야 하는지 알 수 있게 돕습니다"
  - 이유: 시연판은 끝난 거래를 사후에 분석하므로 "피해가 커지기 전에"라는 표현을 없앴다.
- 추론 그래프 노드 종류 라벨 `patch`(`dashboard/src/lib/ontology.js` `KIND_LABELS`)
  - "권고 조치"를 "개발자용 코드 수정 권고"로 바꿨다(라벨만).
  - 노드 이름과 설명은 스냅샷 값 그대로다.

- 분석기, 온톨로지, `response_reasoner`, 내보내기(`demo/**`), 서버, 스냅샷(`dashboard/public/snapshot`)은 바꾸지 않았다.
  - 그래서 리포트 해시, envelope, 온체인 기록 입력(스키마 v2)도 그대로다.
- 확인 결과(사본 트리):
  - 대시보드 시험 전체 통과(`mitigation.test.js`·`copy.test.js` 포함)
  - `node --test demo/test/*.test.js` 152/152. 커밋된 스냅샷이 지금 내보내기 결과와 같다.
  - `build:static` 성공
  - `regress.sh --working-tree` PASS(exit 0, N=272 생성 4파일 PASS)
  - 보호 경로·demo·server·snapshot diff 0
  - 헤드리스 Chrome으로 다섯 가지를 확인했다: 개요 5개(데스크톱, 펌프앤덤프 모바일 390px), 항목 링크 4종 이동, 히어로 문구, 추론 그래프 라벨, 원자료 "감지된 패턴과 경고".

## 5. 남은 것

- 배포자 Risk Score: 팀 데이터를 받으면 `lib/risk.js` 정규화만 고치면 된다. 그러면 항목 상태가 자동으로 바뀐다(감지 / 이상 없음 / 데이터 없음).
- 코드 점검 화면: 생기면 코드 항목의 링크만 바꾼다.
- 출금 차단 경고를 시연하려면 6번째 시나리오(`honeypot_selective_log` 기반)가 필요하다. 별도 단계에서 결정한다.
